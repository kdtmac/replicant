# 技术方案设计与比较的心路历程

> 本文记录了「复制人」项目立项时的六个关键决策及其弃选理由。

## 决策 1：人格怎么建——微调 vs 知识库 RAG vs 上下文人格+记忆流

| 路线 | 代表 | 弃用理由 |
|---|---|---|
| 聊天记录微调 | WeClone | 要先有几年微信记录、训练成本高、产出一次性快照、人格演进不可解释 |
| 个人知识库问答 | Quivr/Khoj | 回答"你知道什么"，不是"你是谁"——没有人格 |
| **上下文人格 + 记忆流（选定）** | Smallville + 斯坦福 1052 人研究 | 访谈即可建档（85% 一致性背书）、prompt 维度可演进、每一步可审计 |

## 决策 2：建档入口——单一口径 vs 多入口

访谈门槛低、质量可控；聊天记录导入量大、风格保真。最终三入口并存（结构化访谈 / 即时聊天 / 上传记录），统一落到同一份档案 schema。

## 决策 3：演进怎么做——隐式连续更新 vs 显式版本化

微调路线的人格漂移是黑盒。选显式版本化：记忆自由写、随便涨，但档案只能被反思产生的 patch 更新，每版带 `diff_reason`、可回看 v1→v2→v3。

## 决策 4：模拟社会底座——复用现成框架 vs 自研

- ai-town：TS/Convex/PixiJS 与 Python 主业不搭，太重
- Concordia：DeepMind 框架灵活但概念复杂
- 选：自研最小 tick 引擎，先把配对、对话、记忆回写、反思跑通，确定性优先好测试

## 决策 5：记忆检索——embedding vs 词元重合

MVP 零外部服务原则，先用词元重合度打分；relevance 函数已做成独立可换的点，未来可热插 embedding。

## 决策 6：LLM 的角色——全权托管 vs 确定性状态机 + LLM 填空

全流程交给 LLM 会玄学、不可测。选定后者：收敛判据、版本写入、记忆打分全在代码里，LLM 只负责内容生成。

## 背书与空白点

- 已验证可行："克隆你"（WeClone 18k 星、Delphi、小冰克隆人计划）与"模拟社会"（Smallville、Concordia、AgentSociety、Project Sid）两个方向各自都跑通了
- 空白点：没有产品让"真实用户对话长出来的复制人"进入共享模拟社会；人格持续演进机制无人系统化——这正是本项目的位置
